## 4. 已知风险与审核优先级

### BLOCK RELEASE 候选

1. **直连 AI 模型 ID 不被官方接口接受。** 这是设置页可见、用户会直接选择的配置；错误 ID 会导致 AI 功能请求失败。必须用官方文档或官方模型列表确认。
2. **集成后完整回归未覆盖 Windows。** 若本次版本宣称修复 Windows，必须由 Windows CI 产物和真实 Windows 机器验证；否则 release notes 必须避免此类承诺。

### 中等风险

1. `wiki_edges` 启动迁移会修改派生关系数据。已有幂等测试和生产数据库副本验证，但审核者仍应检查事务边界、完成标志写入顺序和回滚行为。
2. 图片生命周期涉及 move/copy/delete/rollback。必须重点检查只删除 `.pending` 中由 OpenWiki 拥有的文件，绝不能移动或删除用户导入的外部原文件。
3. PR #42 修改了筛选、分页、回焦、搜索定位共享的 `ContentList.tsx`。需要快速连点、触底加载和搜索旧内容的组合回归，防止显示混类或滚动定位失效。
4. URL 隐私开关默认仍为开启，即默认仍可能把 URL 发给 Jina、把外文内容发给翻译服务；本轮改进是“可见且可关闭”，不是“默认完全本地”。release notes 和官网不得写成所有网络处理默认关闭。

### 已接受但不阻止发版的问题

1. 分类切换仍可能有轻微、非固定延迟；用户决定暂缓进一步优化。
2. Rust `cargo check` 仍有 29 个既有 warning；PR #40 已从 31 降到 29，没有要求本次全部清零。
3. 前端生产构建仍有既有的大 chunk 和 dynamic import 提示，本轮没有新增同类错误。

### 5.3 重点人工测试

1. 复制普通文本：保存、取消、超时均正常，OpenWiki 自己写回剪贴板不会再次捕获。
2. 复制图片/截图：圆形浮窗图标居中且无红叉；展开后缩略图显示；取消和超时不留下 `.pending` 文件；保存后历史图片可打开。

4. 搜索：点击较旧结果后能加载、滚动并高亮，之后手动切换筛选不会被重复重置。
5. URL：失败后重试按钮能恢复；关闭 Jina 后不走 Jina；关闭翻译后不调用翻译服务。
6. Wiki：构造一次编译失败后可手动重试；Q&A 引用边重启后仍存在；图谱切走后停止绘制。
7. 设置：已有 AI provider/API Key/默认模型不丢失；旧模型仍可选；新增直连模型逐项用官方接口或官方 model-list 验证。
8. Windows：至少使用 CI 生成的安装包在 Windows 10 或 11 上完成启动、设置保存和一次内容捕获；若做不到，审核报告必须明确标记未验证。

## 6. 审核输出格式

请独立审核者输出：

1. `BLOCK RELEASE`：会造成数据损坏、应用无法启动、主功能无法使用或新增模型普遍请求失败的问题。
2. `NEEDS FIX`：应在发版前修，但有明确局部修法的问题。
3. `ACCEPTED RISK`：已知但本次可以接受的问题，并说明影响范围。
4. `PASS`：已核实的任务，附代码位置和验证证据。
5. 最终结论：`可以发版 / 修复后发版 / 不建议发版`。

## 7. 发版边界

在项目负责人明确说“发版”之前：

- 不创建 `release-notes/v0.3.22.md`；
- 不修改 `package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`Cargo.lock` 中的版本号；
- 不提交 release commit；
- 不打 `v0.3.22` tag；
- 不推送 tag 或触发 Release Actions。

审核通过并得到明确发版指令后，严格按照 `release-notes/README.md` 执行完整发布流程。
